# 驱动选择与代码维护

## 从实际 SDK 确认接口

读取当前编译目标的 include 路径、设备头文件、HAL/LL 头文件、版本定义与外设初始化源码。确认函数声明、handle 类型、配置结构和启用宏后再编码。

HAL1 常见 `HAL_*` 和 handle/Init 结构；HAL2 的初始化、实例配置和运行接口需根据当前头文件确认，不能把 HAL1 的结构体字段直接搬入。LL 使用直接外设接口，也必须匹配系列和驱动版本。生成器类型不能代替这项判断。

移植官方或第三方驱动时检查：MCU 外设实例、引脚、电气要求、时钟、DMA/IRQ、数据格式、端序、超时单位、内存及所依赖的 HAL API。先保留成熟驱动行为，再调整与当前工程有关的接口。

## 代码归属

| 内容 | 维护位置 |
| --- | --- |
| 生成器能表达的初始化 | 维护 `.ioc`/`.ioc2` 配置，生成后检查代码。 |
| 应用行为与外部器件驱动 | 现有用户文件、模块或明确可保留的用户区域。 |
| 已有手写初始化 | 原有初始化模块，保持顺序和依赖关系。 |
| 生成器不足所需补充 | 最小的独立补充或明确用户区，说明与生成步骤的关系。 |

重新生成时检查用户文件、回调实现和构建目标是否仍存在。用户区标记必须保持完整；不要把应用逻辑放入无法保留的生成段。

MX2 工程还要区分模型工作区、用户源码和导出目录。不要仅凭 `--diff keep_user` 认定导出目录内的编辑受保护；已有手写改动时先导出到新的临时目录，按归属合并初始化和构建变化，保留原用户文件。

## 外设接口选择

依据需求选择阻塞、IT、DMA。简单同步操作优先保持直接接口；异步操作明确 Busy 状态、完成/错误处理、超时和缓冲区所有权，不自动引入通用控制器框架。

新增 `.c/.cpp` 需要接入真正的编译目标；仅复制到目录不保证被构建。C/C++ 混合时检查 `extern "C"`、启动入口和中断符号。重复 ISR/回调定义与弱符号覆盖必须从链接结果确认。

## SDK 特殊集成

部分 SDK 使用预包含头文件、环境宏或生成的外部配置头。符号缺失时沿编译命令、预包含链和宏定义定位；不要为了通过编译绕过 HAL、伪造常量或关闭必要模块。

检查 startup → SystemInit → 运行库 → main → 系统/外设初始化 → 应用的实际顺序。时钟或基础初始化失败时先处理返回值，避免后续使用无效句柄。

依据：[STM32Cube 软件组件](https://www.st.com/content/st_com/en/stm32-mcu-developer-zone/embedded-software.html)、目标 SDK 的驱动头文件、发布说明和官方示例。
