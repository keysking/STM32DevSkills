# 裸机与异步外设

## 主循环和中断交接

把耗时处理放在主循环或明确的状态机。中断中完成必要的数据采集、状态更新和通知；不在 ISR 中进行长时间等待、格式化输出或会依赖低优先级中断的阻塞操作。

共享标志的 `volatile` 只影响编译器访问，不能保证复合操作原子性、数据一致性或多核同步。根据实际共享数据使用短临界区、单生产者/消费者缓冲区或适当的原子操作，并明确溢出行为。

阻塞 API 的超时依赖时基有效；检查初始化顺序、tick 更新、低功耗和中断屏蔽。不要用无限等待掩盖硬件无响应。

## IT/DMA 数据生命周期

- 异步发送或接收开始后，缓冲区保持有效，直到完成、错误处理或成功中止；不要传入马上失效的局部栈数组。
- 发送完成前不要改写正在使用的数据；接收时明确完整帧、半传输、空闲线和循环缓冲区的边界。
- 区分 DMA 搬运完成与外设真正完成发送；例如串口移位寄存器可能仍在发送，需要查对应驱动完成定义。
- 检查返回 Busy/error，避免重复启动覆盖状态；中止后重新启动应重置必要的计数和状态。
- 根据芯片确认 DMA 能访问的内存区域、对齐要求和 cache 一致性。存在 D-cache 时按目标驱动及内存属性处理 clean/invalidate，不能对所有 STM32 一律调用缓存操作。

## 可验证的功能

通信驱动明确数据格式、接口约束及成功条件，例如发送内容、响应、计数或波形。没有板卡时可以检查协议编码、缓冲区行为和构建；硬件时序及电气条件需要实际证据。

低功耗、多核或带安全域的工程继续遵守原有内存、时钟和唤醒规则，依据目标手册确认，不以某个基础示例覆盖现有初始化。

依据：目标 MCU 参考手册、SDK 外设示例及当前 HAL/LL 实现。
