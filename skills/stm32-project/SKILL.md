# STM32 工程管理

## 先识别工程

目标或维护方式尚不明确时，读取[工程识别与维护](references/identify-and-maintain.md)，从实际文件确认芯片、生成器、驱动、构建体系及运行模型。一个目录可能包含多个子工程，选择用户任务对应的目标；配置文件名只能作为线索。

## 选择操作路径

- 新建工程：确认芯片或板卡；未指定构建体系时使用 CMake + Ninja + GCC，未要求 RTOS 时使用裸机。
- CubeMX：读取[传统 CubeMX 工程](references/cubemx.md)。
- CubeMX2：读取[CubeMX2 工程](references/cubemx2.md)。
- 无生成器：适用于已有无生成器工程或用户明确选择的方案，不能仅因本机缺少 CubeMX/CubeMX2 而采用。沿用现有启动、链接和构建组织；需要基础 CMake 工程时使用当前可用的 `ide-project-create`，见工程识别资料。
- 已有工程：保留现有工具链、目录及用户代码，只有任务要求时才转换结构。

创建基础工程后检查目标配置、源码和生成产物；任务包含功能开发时继续配置、编写和构建。后续配置调整与重新生成遵循所选生成器的流程，无需重建工程。

工具路径或依赖缺失时读取[环境](../stm32-env/SKILL.md)。后续硬件设置和已有工程重新生成使用[配置](../stm32-configure/SKILL.md)，应用实现使用[固件](../stm32-firmware/SKILL.md)，编译及产物检查使用[构建](../stm32-build/SKILL.md)。只读取当前子步骤需要的资料，完成后继续原任务。

## 完成条件

工程目标和维护方式明确；基础文件完整且匹配目标；生成结果没有覆盖无关用户代码；按任务完成构建，并说明实际产物及未完成项。
