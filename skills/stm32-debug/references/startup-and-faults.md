# 启动失败、异常与内存

## 启动链路

沿实际工程检查 boot 选择/存储映射 → 向量表与初始 SP → Reset_Handler → SystemInit → 运行库 → main → 系统/时钟初始化 → 外设初始化 → 应用或调度器。

观察 PC/LR、MSP/PSP、复位原因、初始化返回值和关键句柄。停在 `Error_Handler`、`_exit` 或默认 ISR 只能说明当前位置，继续查找进入它的调用链和前一失败条件。

常见问题包括错误镜像/地址、无效初始栈、未启动的外部时钟、超时依赖未初始化、缺少 SDK 环境宏、错误的安全域/内核或 watchdog 复位。

## Fault 现场

先保存现场，再选择是否复位复现。检查当前内核实际支持的 fault 寄存器；部分核心没有完整的 CFSR/BFAR/MMFAR 等设施，按 CMSIS 设备头和架构手册判断。

对支持的内核读取异常状态、有效 fault 地址、异常返回 LR、堆栈帧及堆栈中的 PC/LR。只有相应 valid 位成立时才解释 fault 地址。根据 MSP/PSP、EXC_RETURN、FPU 扩展帧和安全状态确定帧位置，不能无条件按一个固定偏移读取。

用匹配的 ELF 反汇编故障 PC 附近代码，结合访问地址、调用链和对象生命周期判断越界、空指针、栈溢出、非法指令或访问权限错误。优化或栈损坏可能导致 backtrace 不完整。

## 链接与运行内存

核对实际 Flash/RAM 容量、链接段、装载与运行地址、堆和栈、对齐以及 DMA 可访问区。检查启动清零/复制数据段是否覆盖正确区域，外部存储是否在访问前初始化。

配置模型、生成代码和真实时钟源需要一致；初始化出错后未处理返回值可能使后续外设句柄无效。修复后使用原触发条件复查，记录运行结果而不是仅报告构建通过。

依据：当前芯片参考手册、[CMSIS Core](https://arm-software.github.io/CMSIS_6/main/Core/index.html)、实际 startup、链接脚本和 ELF。
