# 配置检查与生成差异

根据任务选择受影响项目，不对每次修改机械执行全部检查。

| 项目 | 应核对的关系 |
| --- | --- |
| 引脚 | 封装引出、板卡接线、复用信号、方向、上下拉、电气类型及调试接口冲突。 |
| 时钟 | 真实晶振/外部时钟输入、启用状态、PLL/分频、总线和外设源、Flash 等待周期及电压范围。 |
| 串行接口 | 实际输入时钟、波特率/时序、引脚、协议模式及物理收发器。 |
| ADC/定时器 | 输入范围与采样条件、触发源、时钟、计数范围、输出极性和中断/DMA 请求。 |
| DMA | 真实请求映射、方向、地址递增、数据宽度、缓冲区长度与可访问内存、完成与错误回调。 |
| IRQ | 向量名、使能、优先级分组、ISR 到驱动处理函数的调用链；FreeRTOS ISR 合法性。 |
| 中间件 | SDK 兼容版本、资源绑定、时基、内存和所需底层驱动。 |

FDCAN、USB、以太网、低功耗等任务进一步查阅目标芯片参考手册及 SDK 示例，发现它们各自的时钟、内存和物理层约束。

## 三层检查

1. **模型**：目标值回读正确、模型没有相关错误；保存后重新加载仍一致。
2. **代码与构建**：实际初始化代码和中断/DMA 关联反映配置，用户修改保留，相关目标构建成功。
3. **板端行为**：任务要求时检查真实频率、引脚波形、串口或协议响应；软件时钟树计算无法证明板卡上安装了指定晶振。

重新生成前明确当前用户改动及保留区域，生成后检查差异。外设初始化通常由配置模型维护，用户行为放在用户区或独立源码。生成器不能表达的补充修改写明原因、位置及下次生成的维护方式。

如果模型成功但代码不变，检查软件工程、生成目标、目标文件是否真正重新生成、文件冲突策略和构建是否引用该目录。如果保存后值恢复，检查保存路径、后端/GUI 会话、实际资源 ID 及生成器的约束求解。
